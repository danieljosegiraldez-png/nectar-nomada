# Especificaciones

El contrato de lo que algo hace, separado del plan de cómo se construye.

Una spec aquí manda sobre la implementación. Si el código y la spec discrepan,
uno de los dos está mal **y hay que decir cuál** antes de tocar nada: los ocho
defectos que costaron caro estaban en la especificación, y el código era fiel.

**Fiel no es exacto.** Cuando Daniel dude de un número, ir a medir algo
independiente en vez de demostrar que el código coincide con su fuente.
