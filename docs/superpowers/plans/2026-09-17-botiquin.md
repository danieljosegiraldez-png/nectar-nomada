# El botiquín del apiario — Plan de implementación

> **Para trabajadores agénticos:** SUB-SKILL REQUERIDA:
> `superpowers:subagent-driven-development` o `superpowers:executing-plans`.
> Los pasos usan casillas (`- [ ]`).

**Objetivo:** que un medicamento veterinario entre al inventario con lo que la
norma exige documentar, que se sepa dónde está y quién responde por él, que
aplicarlo descuente del frasco, y que su vencimiento avise **en el tablero** de
quien puede hacer algo.

**Arquitectura:** el botiquín **no es un módulo nuevo**: es el inventario con
existencias (#382) más lo que un medicamento tiene y un saco de gallinaza no.
Lo del **producto** va en `ConsumableMaterial` y se escribe una vez; lo del
**frasco** va en `ConsumableLot` y se escribe en cada compra. El aviso es de
tirar —se calcula al pintar `/start`—, no de empujar: no hay proveedor de
mensajería.

**Stack:** Next.js 16 · React 19 · Prisma 7 · Postgres · vitest.

**Spec:** `docs/superpowers/specs/2026-09-17-faena-de-colmena-y-botiquin-design.md`
— §B y §4. **La §A —la «faena», preguntar a qué vas antes de enseñar seis
formularios— NO está en este plan**: es navegación, independiente, y lleva el
suyo.

## Restricciones globales

- **Lo desconocido no se convierte en bueno.** `expiresAt` nulo es «sin fecha»,
  no «vigente». `defaultWithdrawalDays` nulo es «sin declarar», y **cero
  declarado es otra cosa** — el Reglamento (UE) 2019/6 lo pide «aunque sea
  cero».
- **Avisa, no bloquea.** Un lote vencido **se puede aplicar** y queda marcado:
  alguien puede estar registrando hoy lo de la semana pasada. Es la doctrina de
  la casa; el spec deja abierta (§5.1) si con medicamentos Daniel prefiere lo
  contrario — hasta que lo diga, se marca.
- **Nada de salud de personas.** Las advertencias van en el material (§B.2,
  decisión de Daniel). Ninguna tarea añade un campo sobre una persona.
- **El enlace al lote es opcional para siempre**, en tratamiento y en consumo.
- **El servicio no inventa datos.** Si el formulario precarga la carencia del
  producto, se VE y se puede cambiar; el servicio nunca rellena en silencio lo
  que el operario dejó vacío.
- **Todo lo del inventario sigue en pie:** el saldo se deriva y nunca se guarda,
  `saldoDeEventos` es la única derivación, el sentido lo pone el tipo de evento y
  no el signo.
- **SQL a mano con los nombres que pone la convención** —`<tabla>_<columna>_fkey`—,
  no abreviados. Esta semana se tropezó dos veces en eso.
- **La base de pruebas compartida puede ir POR DELANTE de git.** Antes de
  «repararla», comprobar si otra sesión aplicó una migración que aún no se ha
  fusionado.
- **`npm run build` y los dos carriles en toda tarea que toque TypeScript**, no
  sólo las pruebas dirigidas: tres guardias de arquitectura cazaron cosas que
  las dirigidas no veían.
- **Commitear ANTES de mutar**, y una mutación que no compila no cuenta como
  flip-test.

**Archivos:** `lib/inventario/vencimiento.ts` (**nuevo**)

- [ ] **Paso 1: la prueba en rojo**

```ts
import { estadoDeVencimiento } from "../../lib/inventario/vencimiento";

const hoy = new Date("2026-09-17T12:00:00Z");

it("sin fecha dice SIN_FECHA, no VIGENTE", () => {
  expect(estadoDeVencimiento({ expiresAt: null, avisarDiasAntes: 30, hoy }).estado).toBe("SIN_FECHA");
});
it("ya pasada dice VENCIDO, con los días", () => {
  const e = estadoDeVencimiento({ expiresAt: new Date("2026-09-10"), avisarDiasAntes: 30, hoy });
  expect(e).toEqual({ estado: "VENCIDO", dias: 7 });
});
it("dentro del plazo de aviso dice POR_VENCER, con los días que faltan", () => {
  expect(estadoDeVencimiento({ expiresAt: new Date("2026-10-07"), avisarDiasAntes: 30, hoy }))
    .toEqual({ estado: "POR_VENCER", dias: 20 });
});
it("fuera del plazo dice VIGENTE", () => {
  expect(estadoDeVencimiento({ expiresAt: new Date("2027-01-01"), avisarDiasAntes: 30, hoy }).estado).toBe("VIGENTE");
});
it("sin plazo de aviso, lo que va a vencer NO avisa — pero lo vencido SÍ", () => {
  // Resolución de este plan (ver «Decisiones»): nulo = no avisar ANTES. Un
  // vencido no es un recordatorio, es un hecho, y en un medicamento es el
  // que no puede callar.
  expect(estadoDeVencimiento({ expiresAt: new Date("2026-09-20"), avisarDiasAntes: null, hoy }).estado).toBe("VIGENTE");
  expect(estadoDeVencimiento({ expiresAt: new Date("2026-09-10"), avisarDiasAntes: null, hoy }).estado).toBe("VENCIDO");
});
it("el día exacto del vencimiento ya es VENCIDO", () => {
  // El borde. Un medicamento «vence el 17» no se usa el 17.
  expect(estadoDeVencimiento({ expiresAt: new Date("2026-09-17"), avisarDiasAntes: 30, hoy }).estado).toBe("VENCIDO");
});
```

**Firma:** `estadoDeVencimiento(e: { expiresAt: Date | null; avisarDiasAntes: number | null; hoy: Date }): { estado: "SIN_FECHA" | "VIGENTE" } | { estado: "POR_VENCER" | "VENCIDO"; dias: number }`

- [ ] **Paso 2–4:** verla fallar, implementar comparando **fechas de calendario**

## Decisiones que toma este plan, y cuánto cuesta revertirlas

1. **`avisarDiasAntes` nulo no calla lo vencido.** El spec dice «nulo = no
   avisar»; este plan lo aplica a *por vencer* y no a *vencido*, porque un
   vencido no es un recordatorio sino un hecho y, con medicamentos y personas
   alérgicas, es el que no puede callar. Revertir: una condición en
   `estadoDeVencimiento` y su prueba.
2. **A quién le llega el aviso: a quien tenga `lot:manage` sobre donde está el
   frasco.** El spec pide «al encargado, y al apicultor cuando no hay otro». Medido:
   no existe búsqueda inversa de quién tiene ámbito sobre una ubicación, y en el
   catálogo el operario de campo y el gerente **tienen los dos** ese permiso. Así
   que el apicultor lo ve cuando no hay gerente —que es lo que Daniel pidió— **y
   también cuando lo hay**. En un aviso de seguridad, que llegue de más es el error
   bueno. Revertir a lo estricto exige escribir la búsqueda inversa, con
   ajustes por asignación incluidos: pieza propia.
3. **`lot:manage` y no `apiary:manage`.** El medicamento es un lote de
   inventario y quien puede actuar sobre él —botarlo, cuadrarlo— es quien tiene
   `lot:manage`. Un `Apiary Colony Event Recorder` como Kenis no lo ve: no puede
   hacer nada con un frasco vencido.
